# Статус проверки версии 0.3.1

Дата подготовки: 20 ноября 2026 года.

## Что выполнено в рабочей среде

Рабочая среда — Linux. Компилятор Swift и macOS SDK отсутствуют.

## Закрытие окна настроек в 0.3.1

Пользователь сообщил, что окно настроек появляется и сразу исчезает. В исходниках найдена связь `NSTextField.action` поля количества с `applySettings`, чей callback закрывает окно. AppKit может отправлять action при окончании редактирования, поэтому такой обработчик не ограничивал применение настроек явным нажатием кнопки или Return.

Удалены target/action поля и явно установлен `sendsActionOnEndEditing = false`. Return обрабатывает существующая кнопка «Применить» через стандартную передачу `performKeyEquivalent` из `NSTextField.textDidEndEditing`; Tab и смена фокуса не применяют настройки. Удалён лишний вызов `makeFirstResponder` перед `selectText`.

Открытие обоих окон перенесено в default-режим основного run loop через `perform(_:with:afterDelay:inModes:)`, чтобы оно происходило после отслеживания меню. Размеры дочерних элементов рассчитываются перед показом, запрос активации выполняется перед `makeKeyAndOrderFront`. Статус доступа обновляется до показа окна справки. Версия приложения добавлена в заголовок меню, чтобы отличать новую запущенную копию от старой.

API и цепочки вызовов проверены по первичным источникам Apple: [окончание редактирования](https://developer.apple.com/documentation/appkit/nscell/sendsactiononendediting), [обработка Return](https://developer.apple.com/documentation/appkit/nstextfield/textdidendediting(_:)), [отложенный вызов в выбранном режиме](https://developer.apple.com/documentation/objectivec/nsobject-swift.class/perform(_:with:afterdelay:inmodes:)) и [асинхронная активация](https://developer.apple.com/documentation/appkit/nsapplication/activate(ignoringotherapps:)). Выполнен независимый обзор изменений. Нативная последовательность событий, из-за которой окно исчезало на Mac пользователя, здесь не воспроизведена. **Исправление не является подтверждением решения прежней проблемы разрешений или запуска перехвата.**

Для этой правки не добавлялись формальные XCTest, повторяющие строки настройки AppKit. В [TESTING.md](TESTING.md) добавлены целевые ручные сценарии: открытие мышью и Return из меню, переход с количества к теме, потеря фокуса, отмена и повторное открытие. Их выполнение на Mac остаётся необходимым.

## Темы оформления в 0.3.0

Добавлены текущая, Liquid Glass, системная, светлая и тёмная темы. Настройки передают количество и тему только после «Применить»; черновой выбор и «Отмена» не записывают UserDefaults. Сохранённая тема загружается при запуске. Панель, предпросмотр и уведомления используют общую поверхность; окно справки и настройки получают соответствующие цвета и appearance.

Проведён независимый обзор переноса одного content view между обычным `NSVisualEffectView` и `NSGlassEffectView.contentView`, размеров вложенных view и координат наведения. Проверен возврат к системной appearance после принудительной светлой или тёмной; динамические цвета рамок пересчитываются при смене appearance. Исправления `clipboardCell` и явного `CGFloat.greatestFiniteMagnitude` сохранены.

По обзору исправлена проверка SDK: одного `#if compiler(>=6.2)` недостаточно, поскольку новый Swift может использовать старый SDK. `build.sh` определяет реальный SDK через xcrun, явно передаёт его в SwiftPM и добавляет `CLIPDECK_HAS_GLASS` только для SDK 26+. В коде все три участка glass дополнительно проверяют этот флаг, версию компилятора и runtime macOS 26. Независимый повторный обзор цепочки не выявил конкретных дефектов. На неподдерживаемой конфигурации Liquid Glass недоступна, используется системное оформление.

Это проверка исходников и согласованности API по документации Apple. **Компиляция с SDK 26, нативный внешний вид пяти тем и переключение системного оформления в работающем приложении здесь не проверялись.** Новых XCTest для визуальных тем не добавлено; ручные сценарии находятся в [TESTING.md](TESTING.md).

## Исправления по логу сборки 0.2.0

Пользователь предоставил результат компиляции Apple Swift 6.3 для `arm64-apple-macosx26.0`: ошибки в `HoverPreviewController.swift` и `OverlayController.swift`.

- В `NSSize` выражение `.greatestFiniteMagnitude` оказалось неоднозначным между `CGFloat` и `Double`. Во всех трёх местах предпросмотра теперь указан `CGFloat.greatestFiniteMagnitude`.
- `ClipboardSlotButton`, наследующий `NSButton`, объявлял `cell: ClipboardCell`, что конфликтовало с унаследованным `NSControl.cell: NSCell?`. Свойство и параметр инициализатора кнопки переименованы в `clipboardCell`; обращения при отрисовке, выборе, наведении и выделении default обновлены. `SlotPresentation.cell` остаётся полем структуры и не конфликтует с AppKit.

Проверены ссылки на переименованное свойство и изменения относительно архива 0.2.0. Исправления подготовлены в 0.2.1 и сохранены в 0.3.1, build 6. Проверки исходников не заменяют компиляцию: успешная сборка этой версии на Mac пока не подтверждена. Новых XCTest для переименования и явного числового типа не добавлено; существующие 53 теста остаются в проекте.

## Компактная панель и предпросмотр в 0.2.0

По исходникам и расчёту геометрии панель с исходными десятью сохранёнными буферами уменьшена до 616 × 110 pt, ячейки — до 48 pt. Добавлена отдельная ячейка «Система». Количество сохранённых буферов настраивается от 1 до 30; дополнительные ячейки располагаются в несколько рядов. Добавлены задержка наведения 0,5 с, отдельная карточка содержимого и задержка закрытия 0,28 с для перехода курсора в карточку.

Выполнен обзор связи контроллеров: область предпросмотра включена в проверку щелчка внутри панели, окна не становятся key/main, устаревшие ответы отсеиваются по поколению. Положение курсора повторно проверяется после изменения размера карточки. Разбор сохранённых данных и уменьшение изображений вынесены в отдельную очередь. Найденное при обзоре обрезание сведений о неподдерживаемых форматах исправлено: эти сведения показываются в прокручиваемой области.

Для нескольких рядов исправлен переход к карточке нижней ячейки через верхние: открытая карточка сохраняется при кратком проходе курсора, а замена выполняется после новой задержки. Ожидающее наведение и текущая карточка используют отдельные поколения. Повторный обзор этого пути не выявил новых конкретных дефектов.

Это **обзор исходников, а не проверка работающего интерфейса**. Нативная компиляция, задержки наведения, прокрутка, сохранение фокуса и расположение карточки на нескольких экранах требуют выполнения на Mac. Для них добавлены отдельные сценарии в [TESTING.md](TESTING.md).

## Системный буфер и количество ячеек

Проверена интеграция отдельной системной ячейки: вставка отправляет native ⌘V исходному приложению без перезаписи системного буфера из снимка предпросмотра. Наблюдение работает только при открытой панели. Раздельные идентификаторы чтения и поколения отсекают устаревшие ответы; чтения приостанавливаются, пока ожидается запись на главном потоке. Отдельный срок ожидания позволяет убрать индикатор подготовки при медленном источнике.

Количество сохраняется в UserDefaults, диапазон ограничен 1…30. Редьюсер проверяет видимый диапазон; хранилище приложения сохраняет до 30 ячеек независимо от выбранного количества. При уменьшении скрытые данные остаются в памяти до выхода, скрытый default становится первым. Смена количества отменяет прежнее взаимодействие до перестройки состояния. Это проверка исходников; работа окна настроек и фактическая сохранность при пользовательских действиях включены в ручной план.

## Исправление по результату сборки на Mac

Пользователь предоставил лог сборки версии 0.1.0 на Apple Swift 6.3 (`arm64-apple-macosx26.0`). Вызов `AppDelegate()` в старом `main.swift` остановил компиляцию с ошибкой `ActorIsolatedCall`: точка входа не имела явной изоляции `MainActor`.

В версии 0.1.1 этот файл заменён на `ClipDeckMain.swift` с декларацией `@main @MainActor enum ClipDeckMain`. Весь синхронный запуск AppKit выполняется в `static func main()` на том же акторе, что и `AppDelegate`. `withExtendedLifetime` удерживает делегат на протяжении цикла событий. Старого файла `main.swift` в целевом модуле больше нет.

Проверены согласованность новой точки входа, отсутствие старого файла, версия в plist и состав обновлённого архива. Это статические проверки; повторная компиляция Swift 6.3 и запуск приложения на Mac пока не подтверждены.

## Исправления, найденные при обзоре

- Сохранение подтверждается отдельно: при ошибке заполнения памяти панель остаётся открытой и снимок можно сохранить в другую ячейку.
- Отложенная вставка проверяет токен запроса, активное приложение и поколение системного буфера непосредственно перед записью; отменённая операция не должна перезаписывать новое копирование.
- Автоповтор клавиши не подтверждает выбор и не теряет событие отпускания клавиши, исходное нажатие которой было передано приложению.
- Таймаут запросов Accessibility назначается и объекту приложения, и объекту окна.
- Устаревшие ответы копирования отбрасываются по идентификатору сессии.

## Что ещё требует Mac

В среде подготовки не выполнены компиляция Swift/AppKit, создание и запуск `.app`, проверка разрешений, внешней вставки, визуального расположения и полноэкранных окон. Сборка не подписана Developer ID и не нотарифицирована; сценарий на Mac создаёт локальную ad-hoc подпись.

Матрица ручных сценариев находится в [TESTING.md](TESTING.md). Она нужна для проверки реальных TextEdit, Safari, Finder, нескольких экранов и источников с отложенной выдачей данных.
